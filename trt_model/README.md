trt model 是用来手搓TRT模型network，从头构建vit，灵活性最高，int16的数据格式，各种自定义算子，通过C和CUDA应该也可以实现位移的硬件算法，但是我不能确定这能否比nvidia将许多算子融合优化的kernel更好，而且工作量过大，各种版本对齐很让人头大，尤其是tensorRT对于int8的支持，几乎局限在QDQ节点的方式（不能直接在network中加进一个int8的constant），很难完全通过自定义实现，这又与手搓的初衷背离，故暂时搁置
如果还想做这个方向，先疏通以下问题：  
1.怎么实现int8的算子流 用不用QDQ，用QDQ对于int16/int32怎么办，trt能支持 fp->Q->int8->OP->int16->DQ->fp的算子融合吗，不用的话怎么贴int8的constant，贴一个fp然后再cast似乎也不太可行，也是什么奇怪的报错  

另外，做好负优化的准备，trt并非最底层，算子内部计算的细节是未知的，手搓出来的性能可能比不过nvidia的既有优化
